# Пульс — учёт предприятия

Учебная full-stack ERP-система для торговли и складского учёта. Проект создан по теме «Клон 1С — учёт предприятия» для производственной практики.

## Что уже работает

- адаптивная панель управления с ключевыми показателями;
- справочник товаров, цены и контроль минимального остатка;
- два склада, остатки и журнал движений;
- продажи с проверкой доступного количества;
- финансовые операции и аналитические отчёты;
- справочник клиентов и поставщиков;
- SQLite-база с демонстрационными данными;
- REST API и атомарное проведение продажи;
- приватный Telegram-бот с белым списком пользователей;
- публичная демо-версия интерфейса на GitHub Pages.

## Стек

React 19, TypeScript, Vite, Recharts, Node.js, Express, встроенный SQLite, grammY.

## Быстрый запуск

Требуется Node.js 22.5 или новее.

```bash
npm install
npm run dev
```

Интерфейс: `http://localhost:5173`  
API: `http://localhost:4000/api`  
Проверка API: `http://localhost:4000/api/health`

Также доступен запуск через Docker Compose:

```bash
docker compose up
```

## Авторизация и роли

API требует JWT для всех операций, кроме проверки состояния и входа. Чтобы создать первого администратора, задайте `JWT_SECRET` (не менее 32 символов), `ADMIN_EMAIL` и `ADMIN_PASSWORD` (не менее 12 символов) в окружении backend до первого запуска. Учётная запись создаётся только если email ещё не зарегистрирован; публичной регистрации нет.

Вход: `POST /api/auth/login` с `{ "email": "...", "password": "..." }`. Передавайте выданный токен в заголовке `Authorization: Bearer <token>`. Токен действует 8 часов. Администратор создаёт сотрудников через `POST /api/auth/users` с полями `email`, `name`, `password`, `role`.

Роли: `admin` (все операции), `director` (обзор и управление), `accountant` (финансы, отчётность и контрагенты), `manager` (продажи, товары, склад и клиенты), `storekeeper` (товары, остатки и движения). Пароли хранятся в виде bcrypt-хеша. Секрет JWT и начальные учётные данные должны храниться только в переменных окружения.

## Telegram-бот

В репозитории нет токена, Telegram ID, реальных товаров, продаж или фотографий. Скопируйте `telegram-bot/.env.example` в `telegram-bot/.env`, заполните секреты и запускайте бот только в доверенной среде.

```bash
set -a
source telegram-bot/.env
set +a
npm run dev -w telegram-bot
```

`ALLOWED_USER_IDS` — закрытый белый список Telegram ID через запятую. Пользователи вне списка не получают доступ к данным.

## REST API

| Метод | URL | Назначение |
|---|---|---|
| GET | `/api/health` | состояние сервера |
| GET | `/api/dashboard` | показатели для главной |
| GET | `/api/products` | товары и общие остатки |
| GET | `/api/stock` | остатки по складам |
| GET | `/api/partners` | клиенты и поставщики |
| GET | `/api/movements` | складские движения |
| GET | `/api/finances` | доходы и расходы |
| POST | `/api/sales` | проведение продажи |

При проведении продажи сервер открывает транзакцию, проверяет остаток, создаёт документ, списывает товар, записывает складское движение и финансовое поступление. Продажа сверх остатка отклоняется.

## Безопасность данных

Файлы `.env`, локальная база SQLite и любые пользовательские выгрузки игнорируются Git. Демонстрационные названия и суммы вымышлены. Для production-развёртывания секреты нужно хранить в переменных окружения хостинга.

## Структура

```text
frontend/      React-интерфейс
backend/       REST API и SQLite
telegram-bot/  приватный бот без личных данных
```

Проект учебный и не заменяет полноценный бухгалтерский или налоговый учёт.
